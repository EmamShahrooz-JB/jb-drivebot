# امنیت JB-DriveBot

## ۱. مدل تهدید

| تهدید | کنترل |
|---|---|
| کاربر ناشناس در تلگرام که ربات را پیدا کند | Allowlist سخت روی `ADMIN_USER_IDS`؛ پاسخ واحد و بی‌اطلاعات |
| فوروارد شدن یک دکمه تأیید حذف به چت دیگر | Callback Data امضاشده با HMAC + انقضا (۱۵ دقیقه) + RefStore تصادفی |
| سرقت دیتابیس (بکاپ، دیسک، لاگ) | توکن‌ها با AES-256-GCM و کلید مشتق‌شده رمزنگاری می‌شوند؛ کد جفت‌سازی فقط هش |
| MITM روی انتقال کد/توکن | فقط HTTPS؛ ابزار محلی `http://` را رد می‌کند مگر `--allow-insecure` و فقط برای loopback |
| CSRF در مرورگر حین OAuth | پارامتر `state` تصادفی و مقایسه constant-time |
| کد مجوز دزدیده‌شده | PKCE (S256)؛ بدون `code_verifier` بی‌ارزش است |
| SSRF از طریق لینک | بلاک‌لیست کامل IP + اعتبارسنجی مجدد Redirect + پین IP در لایه سوکت |
| Zip Slip / Zip Bomb | بررسی نام، symlink، نسبت فشرده‌سازی، تعداد ورودی، سقف مجموع |
| Path Traversal در فایل موقت | `safeFileName` + `resolveInside` |
| افشای توکن در لاگ | `redact()` روی همه خروجی‌ها + فیلد‌های حساس حذف می‌شوند |
| Spam / DoS از سمت خود اپراتور یا اکانت دزدیده‌شده | Token bucket + محدودیت هم‌زمانی صف + سقف حجم |
| عمومی‌شدن ناخواسته فایل | پیش‌فرض خصوصی؛ عمومی‌کردن فقط با دکمه تأیید + ثبت در Audit |
| اسکریپت مخرب در آرشیو | هیچ فایلی اجرا نمی‌شود؛ فایل‌ها فقط آپلود می‌شوند |

## ۲. رمزنگاری

```
APP_ENCRYPTION_KEY (32 بایت، base64)
        │ HKDF-SHA256 (salt="jb-drivebot", info=<purpose>)
        ├── purpose="google-refresh-token"  → کلید توکن تمدید
        ├── purpose="google-access-token"   → کلید توکن دسترسی
        ├── purpose="pairing-transfer-key"  → کلید بسته‌بندی کلید انتقال جفت‌سازی
        └── purpose="telegram-callback-signing" → کلید HMAC دکمه‌ها
```

- الگوریتم: AES-256-GCM، IV تصادفی ۱۲ بایتی، AAD ثابت `jb-drivebot:primary` برای توکن‌های Google.
- قالب ذخیره: `v1:<iv>:<tag>:<ciphertext>` (base64url).
- اثر انگشت GCM: هر دستکاری در ciphertext/tag/AAD/purpose باعث خطای احراز اصالت می‌شود (تست دارد).
- چرخش کلید: `APP_ENCRYPTION_KEY` را عوض کنید → توکن قدیمی باز نمی‌شود → `/connect` مجدد. (چرخش بدون قطعی پیاده نشده است.)

## ۳. OAuth

- نوع کلاینت: **Desktop app** (الزامی).
- Redirect: `http://127.0.0.1:<port>/oauth2callback` — سرور هر `redirect_uri` غیر-loopback را رد می‌کند (تست دارد).
- `access_type=offline` + `prompt=consent` → تضمین Refresh Token.
- حالت پیش‌فرض: تبادل کد روی سرور؛ Refresh Token روی کلاینت مصرف نمی‌شود.
- حالت `local-exchange`: توکن با کلید مشتق از کد جفت‌سازی (HKDF) به‌صورت AEAD بسته‌بندی می‌شود؛ کلید فقط برای عمر همان کد وجود دارد و بعد از استفاده صفر می‌شود (`fill(0)`).
- `/disconnect` هم توکن محلی را پاک می‌کند و هم `revoke` گوگل را صدا می‌زند.
- اگر Google `invalid_grant` بدهد (لغو دسترسی، اپ در حالت Testing)، ربات خودش قطع می‌کند و `/connect` می‌خواهد.

## ۴. جفت‌سازی

| ویژگی | مقدار |
|---|---|
| تولید کد | ۸ کاراکتر از الفبای بدون ابهام (بدون I/O/0/1) ≈ ۴۰ بیت |
| ذخیره | فقط `sha256(code)` |
| عمر | ۱۰ دقیقه (`PAIRING_TTL_SECONDS`) |
| یک‌بارمصرف | بله (`used_at`) |
| تلاش مجاز | ۵ (`PAIRING_MAX_ATTEMPTS`) و Rate Limit ۱۰ درخواست/دقیقه/IP |
| صدور کد جدید | کدهای استفاده‌نشده قبلی باطل می‌شوند |
| سطح دسترسی کد | فقط اتصال حساب؛ هیچ عملیات فایلی با آن ممکن نیست |

## ۵. تلگرام

- **Allowlist**: `ADMIN_USER_IDS` (اعداد). تشخیص با `ctx.from.id`؛ برای callback هم چک می‌شود.
- **Rate limit**: پیش‌فرض ۳۰/دقیقه با burst ۱۰؛ پیام دستور ۲ توکن و کال‌بک ۱ توکن.
- **Callback**: `payload|exp|HMAC-SHA256(payload|exp)` با base64url کوتاه‌شده به ۲۲ کاراکتر (کل سقف ۶۴ بایت تلگرام).
- **تأیید دو مرحله‌ای**: حذف (به سطل)، حذف دائمی، عمومی‌کردن، لغو عمومی، استخراج ZIP، قطع اتصال.
- **ویرایش پیام وضعیت** به‌جای اسپم.

## ۶. شبکه خروجی (SSRF)

تابع `validateTarget`:
1. فقط `http:`/`https:`؛ URL با username/password رد می‌شود.
2. پورت‌های حساس (22, 6379, 5432, 3306, 27017, …) بسته.
3. نام‌های `localhost`, `metadata.google.internal`, `*.internal`, `*.local` بسته.
4. در صورت IP خام: بررسی مستقیم؛ در صورت دامنه: **همه** رکوردهای DNS باید عمومی باشند (اگر یکی خصوصی بود، رد).
5. `guardedLookup` به `http.request` داده می‌شود تا سوکت فقط به آدرسی وصل شود که خودمان تأیید کرده‌ایم (DNS rebinding).
6. هر Redirect: از گام ۱ دوباره.
7. سقف حجم + timeout + تشخیص HTML.

بلاک‌لیست IPv4: `0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.88.99/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4`
IPv6: `::1, ::, fe80::/10, fc00::/7, ff00::/8, ::ffff:<private>, 2002::/16`
